> 本模块的全业务功能验证一律采用 **启动 Spring 服务驱动真实业务链路** 的方式
> （`java -cp` 启动真实应用，覆盖文件映射扫描 / 数据库映射加载 / 定时调度 / Source→转换→Sink 全链路），
> **不使用 JUnit / @SpringBootTest 断言**。

## 1. 模块全业务功能清单

按功能域拆分，共 5 大域。每一功能点即为「全业务」覆盖对象，后续验证矩阵与之对齐。

### 1.1 配置模型（`DatasyncProperties`）

| 编号 | 功能点 | 配置项 | 默认值 | 说明 |
|------|--------|--------|--------|------|
| F1.1 | 模块开关 | `plugin.datasync.enabled` | `true` | 为 false 时整个自动配置不生效 |
| F1.2 | 映射来源 | `plugin.datasync.mapping-source` | `file` | `file` \| `database` 二选 |
| F1.3 | 文件映射目录 | `plugin.datasync.file-mapping.directory-path` | `./datasync/mappings` | 文件模式扫描根目录 |
| F1.4 | 数据库映射开关 | `plugin.datasync.database-mapping.enabled` | `false` | 为 true 时启用 DB 加载器 |
| F1.5 | 表名前缀 | `plugin.datasync.database-mapping.table-prefix` | `datasync_` | 映射表名 = 前缀 + `mapping` / `field_mapping` |
| F1.6 | 数据库轮询 Cron | `plugin.datasync.database-mapping.cron` | `0/5 * * * * ?` | 预留的 DB 轮询间隔（当前版本启动时一次性加载） |

## 2. 全业务验证方式：启动 Spring 服务

「全功能」不以 mock 断言覆盖，而以**真实启动 Spring 上下文**驱动各功能点。

两个可执行应用（均在本模块）：

| 应用 | 路径 | 模式 |
|------|------|------|
| `DataSyncApplication` | `support/DataSyncApplication.java` | `--datasync.mode=file`（默认）\| `database` |
| `DataSyncDatabaseProbe` | `dbprobe/DataSyncDatabaseProbe.java` | H2 探针（模拟 DB 模式） |

### 2.1 编译

```bash
# 父目录执行
mvn.cmd -o "-Dmaven.repo.local=G:/repo" compile -pl :spring-support-datasync-starter
```

### 2.2 classpath 生成（首次）

```bash
mvn.cmd -o "-Dmaven.repo.local=G:/repo" -pl :spring-support-datasync-starter dependency:build-classpath "-Dmdep.outputFile=%TEMP%\opencode\datasync-cp.txt"
```

### 2.3 `java -cp` 直跑文件模式

```powershell
$cp = Get-Content "$env:TEMP\opencode\datasync-cp.txt" -Raw
$classes = "G:\work\spring-support-parent-starter\spring-support-datasync-starter\target\classes"
java.exe -cp "$classes;$cp" com.chua.starter.datasync.support.DataSyncApplication `
  --datasync.mode=file `
  --plugin.ssh.server.enabled=false --plugin.osgi.shell.enabled=false
```

### 2.4 `java -cp` 直跑数据库模式（嵌入式 H2，无需外网 MySQL）

```powershell
java.exe -cp "$classes;$cp" com.chua.starter.datasync.support.DataSyncApplication `
  --datasync.mode=database `
  --plugin.ssh.server.enabled=false --plugin.osgi.shell.enabled=false
```

> 数据库模式默认嵌入 H2（`schema.sql` 建表 + 预置 `db-user-sync`），`DatabaseMappingLoader` 走真实
> `SELECT ... FROM datasync_mapping` 查询链路；加 `--datasync.db=mysql` 才切真实 MySQL。生产 MySQL
> 不可达也不再阻塞数据库模式的本地真实验证。

### 2.5 `java -cp` 直跑 H2 数据库探针（专项验证用）

```powershell
java.exe -cp "$classes;$cp" com.chua.starter.datasync.dbprobe.DataSyncDatabaseProbe
```

> 探针用于专项场景（坏表前缀容错 / params 用例），常规 database 验证直接走 2.4 的
> `DataSyncApplication --datasync.mode=database`（H2）。

> SSH/OSGi 关闭参数原因见第 6 节「已知约束与约定」。
> 自动化运行脚本：`C:\Users\yemen\AppData\Local\Temp\opencode\run-ds.ps1 -Mode file|probe|database -Seconds N`。

### 3.11 网络掉线 / 短线重连（✅ 已验证，`DataSyncReconnectProbe`，PID=5676）

`TcpSyncServer(28979)` + `TcpSyncClient`，完整 4 步动作：

| 步骤 | 动作 | 日志证据 | 状态 |
|------|------|----------|------|
| 1 正常连接 | 服务端启动，客户端 connect | `服务器启动成功 28979` + `客户端接入: client-A` + `isConnected=true` | ✅ |
| 2 数据推送 | 客户端 `send` + 服务端 `publish` | 服务端 `收到数据: batch-1:张三,30 / 李四,25` | ✅ 双向可通 |
| 3 突然掉线 | 服务端 `stop()` | 客户端回调 `onError Socket closed`，掉线窗口 `send` 抛 `RuntimeException` | ✅ 掉线被真实检测 |
| 4 短线重连 | 服务端重启 + 客户端 `disconnect()+connect()` | `重连后 isConnected=true` + `batch-3:赵六,32` 服务端收到 | ✅ 链路自愈 |

汇总：服务端收 3 条消息（2 掉线前 + 1 重连后），接入 2 次/断开 1 次，重连后 `isConnected=true`，**自愈闭环完整**。

> **库语义发现**：`TcpSyncClient` 掉线后仅回调 `onError`，**不会自动复位 `connected` 标志**；
> 短线重连须在上层策略中显式 `disconnect()` + `connect()` 清理旧 Socket 并重建新连接。

- **file 模式**：目录扫描（YAML/JSON/Properties）→ manager → 定时调度 → CSV 读取→转换→写入。**已验证闭环。**

## 6. 已知约束与约定

- **`DataSyncApplication` 硬编码 SSH 配置与 ssh-starter 属性模型冲突**：
  其 `defaults` 设置了 `plugin.ssh.server.authentication.password=admin`（字符串），
  而 ssh-starter 把 `password` 解析为 boolean，触发绑定异常，导致上下文无法启动。
  因此必须追加 `--plugin.ssh.server.enabled=false --plugin.osgi.shell.enabled=false` 绕过。
- **数据库模式默认嵌入 H2，MySQL 为显式参数**：`--datasync.mode=database` 默认用 `EmbeddedDatabaseBuilder`
  + `schema.sql`（预置 db-user-sync），任何环境均可真实启动验证 `DatabaseMappingLoader` 链路；
  连接生产 MySQL 需追加 `--datasync.db=mysql`（URL 硬编码 `172.16.0.40:3306/datasync_test`）。
- **探针必须排除 `DataSourceInspect`**：`datasource-starter` 默认注册 `dynamicDataSource`，
  若探针未加 `@SpringBootApplication(exclude = DataSourceInspect.class)`，`DatabaseMappingLoader`
  **注入的是 SQLite dynamicDataSource（基线脚本只含 db-user-sync 一条）**，自定义 H2 会变成并存的多余库，
  导致预期的测试数据（params 用例等）不出现在加载链路中。`DataSyncApplication` 与
  `DataSyncDatabaseProbe` 均已排除该注册器，使自定义嵌入式数据源成为唯一 `DataSource`。
- **类路径长度**：运行时 classpath 约 16KB，超出 cmd 8191 字符限制，**不能用 bat 脚本直接拼接**；
  用 PowerShell `Start-Process` + classpath 文件（`java -cp "@cp文件"`）方式可稳定启动。
- **调度器轮询粒度**：`SyncDataSchedulerManager 调度间隔: 1 秒`，cron 秒级精度（`0/5`）可实测触发。
- **CSV Sink 是 append 追加**：重复轮次会累积行（文件模式 2 轮 → user-sink 6 行），清 `target/datasync-out*` 后再跑可得到干净输出。
- **Properties 映射字段数组语法不生效**：properties 格式可解析加载并调度执行，但 `mappings[0].sourceField=...`
  这种点分数组写法经 `buildNestedMap` 后不是 `List<mapping>`，加载出的 mapping `mappings=[]`，
  字段转换仅在 YAML/JSON 中可靠。properties 字段映射需改用单段配置或避免依赖字段转换。
- **嵌入式驱动语境：默认走 SQLite（dynamicDataSource）**：未排除 `DataSourceInspect` 时日志出现
  `SQLITE_ERROR`，此时 `DatabaseMappingLoader` 实际查询 SQLite 基线库；排除后走自定义 H2 内存库
  （日志 `jdbc:h2:mem:datasync-db-probe`）。两种语境下 `JdbcTemplate` 查询链路本身一致。
- **表结构与数据初始化**：`schema.sql` 由启动类用 `EmbeddedDatabaseBuilder.addScript` 执行（测试用）；
  生产由 `spring-support-datasource-starter` 执行 `db/init/V1.0.0__init_datasync_mapping.sql` 建表。
- **TcpSyncClient 掉线后需显式重连**：`connected` 标志在掉线时不会自动复位，仅回调 `onError`；
  短线重连须在应用层 `disconnect()` + `connect()` 重建链路（见 3.11）。
