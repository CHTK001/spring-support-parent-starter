## 启动类

- `com.chua.starter.datasync.support.DataSyncApplication`：文件模式（`--datasync.mode=file`）/
  数据库模式（`--datasync.mode=database`，默认嵌入 H2；`--datasync.db=mysql` 切真实 MySQL）
- `com.chua.starter.datasync.dbprobe.DataSyncDatabaseProbe`：数据库模式专项探针（坏表前缀容错 / params 用例）
- `com.chua.starter.datasync.dbprobe.DataSyncDisabledProbe`：enabled=false 装配关闭探针
- `com.chua.starter.datasync.dbprobe.DataSyncLoadProbe`：并发 + 吞吐专项探针（3 映射同 cron、每源 5 万行）
- `com.chua.starter.datasync.dbprobe.DataSyncReconnectProbe`：网络掉线/短线重连专项探针（TcpSyncServer/SyncClient）

## 执行命令

```bash
# 文件模式
java -cp "@%TEMP%\opencode\datasync-cp.txt" com.chua.starter.datasync.support.DataSyncApplication ^
  --datasync.mode=file --plugin.ssh.server.enabled=false --plugin.osgi.shell.enabled=false

# 数据库模式（嵌入式 H2，无需外网 MySQL）
java -cp "@%TEMP%\opencode\datasync-cp.txt" com.chua.starter.datasync.support.DataSyncApplication ^
  --datasync.mode=database --plugin.ssh.server.enabled=false --plugin.osgi.shell.enabled=false

# 数据库专项探针（H2）
java -cp "@%TEMP%\opencode\datasync-cp.txt" com.chua.starter.datasync.dbprobe.DataSyncDatabaseProbe

# 装配关闭探针
java -cp "@%TEMP%\opencode\datasync-cp.txt" com.chua.starter.datasync.dbprobe.DataSyncDisabledProbe ^
  --plugin.datasync.enabled=false

# 并发 + 吞吐专项探针（3 映射同 tick、每源 5 万行 CSV）
java -cp "@%TEMP%\opencode\datasync-cp.txt" com.chua.starter.datasync.dbprobe.DataSyncLoadProbe

# 断线重连专项探针（TcpSyncServer:28979 + TcpSyncClient）
java -cp "@%TEMP%\opencode\datasync-cp.txt" com.chua.starter.datasync.dbprobe.DataSyncReconnectProbe
```

## 测试结果详情

### 1. 文件模式（mapping-source=file）

映射目录：`./src/main/resources/datasync/mappings`

| 映射ID | 文件 | source | sink | 字段映射 |
|:-------|:-----|:-------|:-----|:---------|
| user-sync | user-sync.yaml | user-source | user-sink | name→user_name(toString)、age→user_age(toInteger) |
| order-sync | order-sync.json | order-source | order-sink | orderId→order_id(toString)、amount→order_amount(toDouble) |

结果：`已加载映射数=2`，DataSyncServer 启动成功 ✅

### 2. 数据库模式（mapping-source=database，`DataSyncApplication --datasync.mode=database`）

数据源：嵌入式 H2（`schema.sql` 建表 + 测试数据），表前缀 `datasync_`，**无需外网 MySQL**

| 映射ID | input | source | output | sink | 字段映射 |
|:-------|:------|:-------|:-------|:-----|:---------|
| db-user-sync | user-input | user-source | user-output | user-sink | name→user_name(toString) |

结果：`数据库加载映射: mappingId=db-user-sync` + `已加载映射数=1`，cron 0/5 每 5s 写入
`target/datasync-out-db/user-sink.csv`（`{user_name=张三/李四/王五}` ×2 轮），DataSyncServer 启动成功 ✅

> 生产对接 MySQL：追加 `--datasync.db=mysql`（URL 硬编码 `172.16.0.40:3306/datasync_test`）。

## 关键修复记录

| 问题 | 修复 |
|:-----|:-----|
| 两个启动类同包冲突（ConflictingBeanDefinitionException） | DataSyncApplication 用 `datasync.mode` 切换；探针独立在 `dbprobe` 包 |
| datasource-starter 注册 dynamicDataSource 覆盖自定义 H2，`DatabaseMappingLoader` 注入 SQLite 基线（只有 db-user-sync 一条） | `@SpringBootApplication` 排除 `DataSourceInspect`（两启动类均加），自定义 H2 成为唯一 DataSource |
| Spring Boot `dataSourceScriptDatabaseInitializer` 重复执行 schema.sql 导致主键冲突 | `spring.sql.init.mode=never`，表由 EmbeddedDatabaseBuilder 统一建 |
| `exec:java` 传递 `-Ddatasync.mode` 到不了子进程 | 改用 `java -cp` 直跑 + 命令行参数 `--datasync.mode=` |
| 修改 schema.sql 后忘记重编译导致 target 副本带 BOM 报 H2 语法错 | 修改 resources 后必须重新 `mvn compile` 使副本无 BOM |
| 数据库模式硬编码 MySQL，本地环境不可达无法启动 | `--datasync.mode=database` 默认嵌入 H2（schema.sql）直接真实启动；MySQL 改由 `--datasync.db=mysql` 显式启用 |
| 并发/吞吐探针 | 新增 `DataSyncLoadProbe`（3 映射 5 万行 ×3，验证并发与吞吐量级） |
| 断线重连探针 | 新增 `DataSyncReconnectProbe`（TcpSyncServer/SyncClient 掉线检测 + 重连自愈） |
| `TcpSyncClient` 掉线语义 | 掉落线仅回调 `onError`，`connected` 标志不复位；重连须显式 `disconnect()`+`connect()` |
