# 自研任务调度模块架构图

> spring-support-job-starter 4.0.0.42
> 模块角色: 提供 `@Job` 注解、Spring `@Scheduled` 注解扫描,以及 三模式 (SCHEDULER/EXECUTOR/SINGLE) 装配

## 1.a 持久化与日志落库 (MyBatis-Plus 路径)

```
[LeaderLoop] ──► JobRepository ──┬──► InMemoryJobRepository (默认)
                                  └──► MybatisJobRepository (classpath 有 BaseMapper 优先)
                                       │
                                       └─► JobMapper.selectList(...) ──► sys_job 表

[SchedulerSyncBinder 收到 task-log] ──► JobLogSink ──┬──► StdoutJobLogSink (默认)
                                                       └──► MybatisJobLogSink (classpath 有 BaseMapper 优先)
                                                            │
                                                            └─► JobLogMapper.insert(...) ──► sys_job_log 表

业务方启用 MyBatis-Plus 时:
  @MapperScan("com.chua.starter.job.support.store")  // 扫描本模块 Mapper
```

## 1.b Leader 选主 (MySQL 行锁路径)

```
ClusterElectionHeartbeat.start() ── scheduledAt = lease/3 ──┐
                                                              │
                                                              ▼
                               ┌─── tick() ─── resolver.tryAcquire(group, nodeId, lease) ──┐
                               │                                                            │
                               │                                                            ▼
                               │              MysqlLeaderElectionResolver
                               │                                                            │
                               │              UPDATE sys_job_cluster
                               │                 SET leader_node=?, lease_until_ms=?, version=version+1
                               │               WHERE cluster_id=?
                               │                 AND (leader_node IS NULL
                               │                      OR leader_node=?
                               │                      OR lease_until_ms &lt; now)
                               │                                                            │
                               │                  rows=1 (受 MySQL 行锁串行化)           <────┘
                               ▼
                  LeaderElector.markLeader(group)  或  release()
                               │
                               ▼
                        JobLeaderLoop.tick()  ──  preReadSql (每秒)
```

多节点行为:
- A 节点先抢到 → B 节点同一次 tryAcquire 返回 rows=0 → B 不进入 Leader
- A 节点崩溃/网络分区 → lease_until_ms 过期 → C 节点下次 tick 抢占成功
- 默认 resolver: `InMemoryLeaderElectionResolver` (单机或调试)

## 2. 配置树

```
plugin.job
├── enable                : boolean   (默认 true, 引入即开箱即用)
├── role                  : enum      (SCHEDULER | EXECUTOR | SINGLE, 默认 SINGLE 单机自闭环)
├── node-id               : string    (留空自动按 hostName-pid 推导)
│
├── cluster
│   ├── group             : string    (默认 "default")
│   ├── scan-interval-ms  : long      (默认 1000, 即每秒一次)
│   ├── pre-read-ms       : long      (默认 5000, 预读未来 5s 到期任务)
│   └── lease-seconds     : int       (默认 15, Leader 租约时长)
│
├── sync
│   ├── scheduler         : SCHEDULER / SINGLE 角色
│   │   ├── listen-host   : string    (默认 "0.0.0.0")
│   │   └── listen-port   : int       (默认 8081)
│   └── executor          : EXECUTOR 角色
│       ├── server-url    : string    (留空则 EXECUTOR 启动失败)
│       ├── reconnect-base-ms  : int  (默认 500)
│       └── reconnect-max-ms   : int  (默认 30000)
│
└── pool
    ├── virtual             : boolean   (默认 true, per-task 虚拟线程执行器)
    ├── core-size         : int       (默认 16, 仅 virtual=false 生效)
    ├── max-size          : int       (默认 64, 仅 virtual=false 生效)
    └── queue-size        : int       (默认 128, 仅 virtual=false 生效)
```

## 4. 同步通道 topic 约定

| Topic | Producer | Consumer | Payload |
|-------|----------|----------|---------|
| `job-cmd` | `JobLeaderLoop` → `SchedulerSyncBinder.publish` | `ExecutorSyncBinder.subscribe` → `JobSyncBus.publish` | `String` (handler name) |
| `job-log` | `JobExecutor.invoke` → `JobSyncBus.publish` → `ExecutorSyncBinder.send` | `SchedulerSyncBinder.addListener` → `JobLogSink.write` | `JobLogEvent` (record) |
| `job-reg` | Executor 启动时 | Scheduler 监听器 (仅日志) | `Map<String,Object>` (节点注册信息) |

---

## 5. 异常路径

```
[T1] Scheduler 推 cmd, Executor 已下线 → publish 失败, 写 warn, 不抛异常
[T2] Executor 收到 cmd, handler 不存在   → 立即构造 skipped JobLogEvent 上行
[T3] Executor handler.execute() 抛异常   → 构造 failure JobLogEvent 上行
[T4] Executor 上行 log 时长链断           → send 失败, 写 warn, 该条 log 丢失
[T5] SINGLE 角色 handler 抛异常          → 进程内 JobLogSink 落库, 不抛
```
