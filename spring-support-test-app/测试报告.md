## 6. 只读优先于所有权限（ReadOnlyRealTest，4/4 通过）——新增功能

| 用例 | 条件 | 预期 | 结果 |
|---|---|---|---|
| readonlyFieldBlocksWriteButAllowsRead | 会话用户 `readonly=true`（账号级字段，无 READ_ONLY 角色），持 user:query + user:delete | GET query 200；POST delete 403（只读字段优先于权限码） | ✅ 通过 |
| readOnlyRoleBlocksWriteButAllowsRead | 会话用户角色含 READ_ONLY，持 user:query + user:delete | GET query 200；POST delete 403（只读优先于权限码） | ✅ 通过 |
| normalRoleAllowsWriteWithPermission | 普通角色持 user:delete | POST delete 200（正常权限流不受影响） | ✅ 通过 |
| readOnlyOverridesSuperAdmin | 角色 READ_ONLY + SUPER_ADMIN | POST delete 403（优先于所有权限，超管也不例外） | ✅ 通过 |

说明：`PermissionInterceptor` 在权限校验**之前**检查只读——账号级 `readonly` 字段（OAuth 服务端数据库返回，`UserResume.readonly`，推荐）或 `READ_ONLY` 角色（兼容兜底）任一命中即生效；非安全方法（POST/PUT/DELETE/PATCH）一律拒绝，GET/HEAD/OPTIONS 放行；无 HTTP 请求上下文（非 Web 调用）不阻断。**只读标记等用户数据全部来自 OAuth 服务端数据库查询（UserResume），配置文件不承载业务数据**。

## 框架缺陷修复记录（本批次发现并修复）

| 缺陷 | 修复 |
|---|---|
| `CacheConfiguration`（cache-starter）方法签名引用 RedisSerializer 且无类级守卫——无 redis 依赖时类加载即崩 | 补类级 `@ConditionalOnClass(name="...RedisSerializer")` 守卫（ASM 求值，无 redis 整体退避） |
| `TcpProtocol`（oauth-client）`verifyFingerprint` 覆写返回类型与接口不符（重构残留）→ 编译失败 | 返回类型改为 `FingerprintVerifyResult` |
| `TcpProtocol` 使用 `OauthClientRuntimeContext` 缺 import → 编译失败 | 补 import |
| `@Permission` `@Target(METHOD)` 不含 TYPE，与拦截器类级支持不一致 | `@Target` 增加 `TYPE` |
| `ApiProperties.GrayConfig` 仅 getter 无 setEnable——`plugin.api.gray.enable` 无法绑定；且 enable 默认 false 违反"默认开关默认开启"约定 | 补 `setEnable`；默认值改 `true`（灰度非实验性功能） |
| `ApiFeatureConfiguration`（common-starter）`@PostConstruct` 扫描期解析 RequestMappingHandlerMapping 触发 WebMvcConfigurer 集合解析 → 循环引用（该配置从未自动注册，首次真实装载暴露） | 扫描延迟至 `SmartInitializingSingleton.afterSingletonsInstantiated` |
| `ApiVersionRequestMappingHandlerMapping` 从未注册；注册后也无法取代 Boot 4 默认映射（EnableWebMvcConfiguration 继承 DelegatingWebMvcConfiguration，映射为继承 Bean，竞争式 @Bean 不退避 → 同路径多版本 Ambiguous mapping） | 改经 Boot 官方扩展点 `WebMvcRegistrations#getRequestMappingHandlerMapping()` 装配（Boot 4 包 `org.springframework.boot.webmvc.autoconfigure`），接管生效 |
| `ApiVersionCondition` 用 `getQueryString()` 手工解析版本参数（MockMvc 下为 null → 参数路由失效退化为匹配最大版本；真实环境存在编码/嵌套解析问题） | 改用标准 `getParameter(VERSION_PARAM)`（匹配与 latest 判断两处同步修正） |
| collapse-demo（主仓库）`DynamicDatasourceTest.defaultRouting` 失败：无 @DS 时默认路由未落主库（此前未配置 spring.datasource） | 按已验证的 master 语义修正：collapse-demo 补 `spring.datasource` 主库配置 + 断言主库数据（跨仓库 primary+@DS 语义一致），套件 17/17 全绿 |

## 框架观察（如实记录）

| 观察 | 说明 |
|---|---|
| `ApiConfiguration`/`ApiFeatureConfiguration` 未注册为自动配置（AutoConfiguration.imports 无条目） | 应用需 `@Import` 或自行注册（测试应用已应用级 `@Import(ApiConfiguration)`；ApiFeatureConfiguration 仅灰度测试类导入） |
| 数据源分片引擎未激活 | 依赖已显式装配（m2 4.0.0.42 + 包路径匹配 + shardingsphere-jdbc 5.5.2 在 m2），`ShardingAutoConfiguration` 仍未激活——需专项排查 ShardingSphere 5.5.2 集成（配置类/规则构建），测试保持条件跳过 |
| `ConcurrentEndpoint`（utils-support-springboot-starter）类级未标注 `@WebEndpoint`/`@Endpoint`，方法仅有 `@ReadOperation`——非 actuator web 端点，经 `/actuator/...` 不可达（实测 404） | 演示应用经自建控制器 `/api/strategy/monitor/**` 委托真实 Bean 暴露为 HTTP 接口；建议后续在主仓库补 `@WebEndpoint(id="concurrent")` 注解以恢复 actuator 可达 |
