## 二、本轮全站可点击控件实测（真实点击，非静态走查）

### 1. 题库管理 `/edu/question`（核心工作流回归）
- 单条「驳回」→ 弹窗「驳回题目」；**空理由提交被拦**：提示 `驳回理由不能为空`、弹窗不关；
  填「验收：选项表述需复核」→ 提交 → 首行变 `驳回 ×2`（状态与次数同时落库）
- 单条「通过」→ 无二次确认直接生效 → `已通过 ×3`
- 批量驳回（勾 2 行）→ 弹窗标题「批量驳回」、文案含题量 `批量驳回 2 题，请填写理由`；
  空理由同样被 `驳回理由不能为空` 拦住 → 填理由提交 → 两行分别 `驳回 ×4` / `驳回 ×2`
- 批量通过（勾 2 行）→ 二次确认 `确认批量通过 2 题吗？` → 点「通过」→ `已通过 ×5` / `已通过 ×3`，
  提交后勾选自动清空、批量按钮回到 `disabled`
- 审核状态筛选：切「待审核」→ `共 52 条`（全量 161 收敛），口径正确

### 3. 代入查看（本轮修复项）
- **正常链路**：代入 → URL `/edu/student`、横幅「管理员代入查看中 · 本页数据属于该学生，且为只读」、
  **0 个阻塞弹窗**、「退出代入」可点 → 回 `/edu/student-login`，`sessionStorage.__impersonateAccessToken__` 长度归 0
- **令牌被踢链路（修复 1）**：另一浏览器重新登录 admin 把源令牌踢下线后点「代入」，
  后端 `POST /v2/edu/dimension/students/impersonate` 返回 **HTTP 401**（23:55:39 与 00:26:29 两条实测），
  前端走标准过期流程回 `/login`，不再出现含糊的「未认证」提示
  - 实现：`EduDimensionService.impersonateStudent` 把签发失败且信息匹配
    未认证/未登录/已失效/已被禁用/黑名单/数据异常（或 code 401）升级为
    `new OauthException("登录状态已失效，请重新登录", 401)`，由 `OauthExceptionAdvice` 映射回 401
  - 提交：后端 `b0a4307e8`（已推送）
- **首登改密弹窗死锁（修复 2）**：代入的学生若 `student_pwd_must_change=1`，原实现会弹不可关闭的
  「首次登录：请修改初始密码」（无 X、ESC/遮罩禁用、无取消），把管理员锁死在代入页、
  「退出代入」点不到。改为 `load()` 里 `&& !impersonating.value` 时不唤起该引导；
  实测代入后 `dialogs=0`、退出按钮可点。前端源码在 `051cfbd64`（已推送），r31 产物 md5 `dee4c65c`
