## 6. 本轮发现并修掉的问题

### 6.1 验收工具的 4 个真漏洞（都已修，`sh -n` 全过）

1. **登录失败会伪装成「跑很久」**：4 个脚本登录失败 → 空 token → `scan` 401 → 空 taskId 轮询**死等 10 分钟**
   （06:04:15 实证 `未找到有效Token - /v2/edu/marking/scan`）。改为登录重试 6 次，仍拿不到 token/taskId 立刻 `exit 9`。
2. **`run-all-stable.sh` 完全不校验各段退出码**：某段失败也照样「成功」。补 `rc=$?` 校验，非 0 整轮重来。
3. **`final-accept.sh` 用 `sh xx.sh | grep`，退出码被 `grep` 吃掉**：空结果也会被写成 `[VALID]`。重写为 v2，落盘取 rc 并向上传播。
4. **`probe-determinism.sh` 永远 exit 0**：那句「分数序列均为 $first」从未真正比对，只是打印。
   改为 `mism` 计数逐次比对，`done==N && mism==0` 才 exit 0，否则 exit 7。

### 6.2 判据漏洞：一个「被看门狗中止却仍报完成」的任务曾被判 PASS

r3 轮日志归因时发现任务 `f17b0c8cfa7246b7afdbb3b70a2de31b`（paper 9003 降质）：

```
06:27:41 ERROR OpenAI 对话请求失败: 504: Unknown
06:27:41 WARN  [EduAi] AI 阅卷失败，回退相似度匹配
06:28:53 ERROR [EduAi] 阅卷任务处理超时（>300s），已中止: taskId=f17b0c8c…
DB:  st=2(完成)  total=21 done=21  err=处理超时（>300s），已中止
     source 分布: AI x19 + FALLBACK x2（那 2 题仍判 5 分）
```

三个问题叠加：**①** 300s 看门狗打了「已中止」但**并没有真正中止**，任务继续判完 21/21；
**②** 最终 `status=2`（完成）而 `error` 字段留着「已中止」，**状态与错误自相矛盾**；
**③** 我的段1 判据只看行数/满分项，**这种任务会被判 PASS**。
（诱因：`timeout-millis=180000`，两次上游调用就可能超过 300s 预算。）

处置：
- **判据侧**：给 9003 两个用例补 `total=21 done=21` 与 `err=-` 断言（`hard-test.sh` 一直打印 `err`，只是没断言），
  段1 断言数由 18 增至 26；**整轮重跑**（r4 轮）确认 5 个用例全 `err=-`、看门狗超时 0、AI 失败 0。
- **产物侧**：本轮**未改产品源码**（授权范围内的并发会话正在改采集链路，不宜交叉改动）。
  上表 ①② 建议作为**待确认项**交产品侧：看门狗是否应真正中断、`status` 与 `error` 是否应互斥，
  以及 300s 预算与 `timeout-millis` 的取值关系。
