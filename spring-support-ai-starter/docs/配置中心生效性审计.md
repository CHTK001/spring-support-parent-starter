# 配置中心「是否真有后端实现」审计

> 审计日期：2026-11-12（同日完成收口）
> 范围：`spring-support-ai-starter`（+ `spring-support-channel-starter` 的同名 health provider）
> 口径：只统计**业务消费方**的读取点（`GlobalSettingReader.getXxx(group,key)` / `SysAiGlobalSettingService.getValue(...)`）。
> provider 里的 `SettingItem` 声明、`AiGlobalSettingDTO` 字段、`AiGlobalSettingServiceImpl.FIELD_MAP` 的 get/put **一律不算生效**。
>
> 性质：静态 grep 审计 + 人工抽样复验 + 逐项接线；运行时验证见各条备注。

## 二、收口结果（2026-11-12）

**原则**：能接到真实消费点的就接线；能力根本不存在的就删声明，不给「填了也不生效」的入口。

### 2.1 已接线（此前零读取 / 死字段）

| group | key | 现在的真实消费点 |
|---|---|---|
| security | `security_rate_limit_enabled` / `security_ip_enabled` / `security_connection_budget_enabled` / `security_body_limit_enabled` / `security_request_timeout_enabled` / `security_request_timeout_millis` | 5 个 `Gateway*Filter` 各自 `doFilterInternal` 前判开关；新增 `GatewayRequestTimeoutFilter`（TTFB 看门狗，默认 60s）；6 个过滤器由 `AiGatewaySecurityAutoConfiguration` 注册（此前**从未被实例化**，整组 16 项全部无效） |

### 2.2 已删除（能力不存在或与其他分组重复）

| group | key | 删除理由 |
|---|---|---|
| runtime | `factory` / `provider_app_key` / `provider_app_secret` | `ChatClientSettings` 的唯一出口 `createSetting(boolean)` 全仓零调用；供应商凭据真实来源是 `sys_ai_manufacturer` / `sys_ai_model_key` 表 |
| runtime | `input_optimization_enabled` | 真实开关是 `input.optimizer_enabled`（`AiInputOptimizeServiceImpl:147` 真读）；同名两开关只会让人关错一个 |
| runtime | `protocol_server_port` | 协议端点挂在应用主端口，不存在独立监听；全仓无任何端口消费方 |
| paper | `layout_threshold` / `ocr_threshold` / `device` | 模型级参数（`ModelParamBridge` 进程内按模型名共享），在 paper 组再声明一份只会与 layout / ocr 分组互相覆盖；真源留在各自分组 |
| paper | `max_pages` | `PaperClient` 的识别入口只接收单张图片字节，全仓没有任何分页 / 多页循环 |
| image | `segment_model` / `quality_enabled` | `ImageRecognitionClientManager` 只装配 classify / detect / captioning / 超分，没有分割与质量评估实现 |
| 全局 DTO | `enableCache`(global.enable_cache) / `stream`(global.stream) / `workshop.storage_dir` / `workshop.max_upload_size_mb` / `workshop.allowed_extensions` | 只在 DTO 与 FIELD_MAP 之间往返，无 provider 声明、无任何业务读取点；PUT 成功、GET 回显、实际无行为 |

### 2.3 审计结论修正

| 条目 | 原结论 | 实际 |
|---|---|---|
| `runtime.enabled`（DTO `chatClientEnabled`） | 零读取 | **真实生效**：`ChatClientSettingsResolver:44` 读取，false 时抛 `IllegalStateException` |

## 三、安全组接线细节（本轮新增）

- 新增 `security/GatewayRequestTimeoutFilter`：**首字节超时（TTFB）**语义，不是总时长 —— `/v2/v1/**` 是 SSE 长连接，按总时长掐断会打断正常对话。到点未提交响应写 504；已提交则不动。
- 新增 `configuration/security/AiGatewaySecurityAutoConfiguration`：注册 6 个 `Gateway*Filter`（order 10/20/30/40/50/60，`/*`，`setAsyncSupported(true)`）与 `GatewayRateLimiter`（`@ConditionalOnMissingBean`，默认本地滑动窗口；`plugin.ai.security.rate-limit-store=redis` 才切 Redis）。
- 修掉 `GatewayConnectionBudgetFilter` 与 `GatewayBodySizeFilter` 的「过滤器链被调两次」（下游 handler 会执行两遍）。
- 已在 `META-INF/spring/...AutoConfiguration.imports` 注册。
- `security_ip_enabled` 语义：关闭时**黑名单**不生效、白名单始终生效（白名单是放行名单，不随总闸关闭）。

## 五、遗留关注点

1. **`health` 组重复声明**：`spring-support-channel-starter` 也有一份 `HealthGlobalSettingProvider`（8 项，比 ai-starter 版少 3 个 `channel_circuit_*`）。目前靠 `GlobalSettingInitializer` 按 group 去重，谁先注册谁赢；channel-starter 版赢的话，`ChannelCircuitServiceImpl` 在读的 3 项会在界面上消失。
2. **安全组默认值上线影响**：`security_*_enabled` 默认 true、QPM 60/200/600、包体 8MB。接线后这些默认值开始真正拦截 `/v2/v1/**` 与 `/v2/ai/**`，上线前需评估上传类接口的包体上限与调用频率。
3. **`runtime.temperature` / `max_tokens` 的层级**：只有「模型登记」「角色配置」都没给值时才会落到设置中心，避免覆盖用户为单个模型 / 角色调过的参数。
