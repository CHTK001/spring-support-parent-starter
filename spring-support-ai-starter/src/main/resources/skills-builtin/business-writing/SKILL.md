# 商务写作指南

## 一、通用原则

- 先想清楚「读者是谁、要他做什么」：知会类、决策类、行动类文档写法完全不同。
- 结论先行（BLUF）：第一段给出结论/请求，理由与细节往后放。
- 一段一个意思，段首给主题句；能用列表不用长段落，能用表格不用文字罗列。
- 语气专业克制：少用感叹号与情绪化措辞；批评对事不对人。

## 二、工作邮件

- 主题行写清事项与所需动作：`【需确认】Q4 预算表修订 - 周三前反馈`。
- 结构：一句背景 → 核心信息/请求 → 截止时间 → 附件说明。
- 请求类邮件明确「谁、做什么、什么时候」，多个收件人时指定责任人（@某人）。
- 回复线程时保留上下文但精简引用；新增议题换新线程，别让一条线程塞三件事。

```text
主题：【需决策】客服系统选型 - 建议采纳方案 B

各位好：
背景：现客服系统 12 月合同到期。
请求：请在周四例会前确认采用方案 B（对比见附件第 2 页）。
如需补充信息，随时找我。

附件：客服系统选型对比（3 页）
```

## 三、周报与月报

- 三段式：本周结果（做了什么、达成什么）→ 数据/进度对照目标 → 下周计划与需要的支持。
- 写「结果」不写「过程」：「完成 A 模块联调并上线」优于「这几天在弄 A」。
- 风险与求助要写明：影响什么、需要谁、什么时候前解决——别等领导来问。
- 数字有对照：目标值、完成值、偏差与原因，一眼看得出健康度。

## 四、方案与建议书

- 骨架：背景与问题 → 目标与衡量标准 → 方案概述（2~3 个候选）→ 推荐方案与理由 → 资源与排期 → 风险与对策。
- 选项对比用统一维度表格（成本、周期、风险、收益），别只夸推荐项。
- 决策者视角：先回答「为什么要做、为什么是现在、为什么是你这个方案」。
- 落地部分具体到里程碑、责任人与验收标准。

## 五、汇报材料

- 金字塔结构：中心结论 → 分论点（不超过 3 个）→ 事实与数据支撑。
- 每页一个观点，标题直接写结论（「渠道 A ROI 高于均值 40%」）而不是「渠道分析」。
- 数据图表自解释：坐标轴、单位、口径、时间范围标注完整。
- 预演问答：准备 3~5 个最可能被追问的问题与数据出处。

## 六、对外函件与公告

- 正式函件要素：称谓、事由、正文、请求/答复方式、落款与日期。
- 公告写清「谁、什么时间、什么变化、对您的影响、需要做什么」，FAQ 兜住高频疑问。
- 涉及价格、条款、责任划分的表述逐字校对；歧义表述宁可重写。

## 七、常见坑

- 抄送泛滥：只发给需要知道/需要行动的人。
- 「尽快」「 ASAP」：给出具体截止时间。
- 附件不说明：正文一句话概括附件内容与页数。
- 长篇铺垫：三段还没进入正题的邮件会被跳读。

## 八、检查清单

- [ ] 第一段能看到结论或请求
- [ ] 行动项有责任人与截止时间
- [ ] 数字有目标对照与口径
- [ ] 方案有选项对比与推荐理由
- [ ] 发送前检查收件人、附件与错别字
