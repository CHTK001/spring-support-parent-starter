# 费曼学习法

## 一、核心思想

- 如果你不能用简单的语言把一个概念讲给外行听，说明你还没有真正理解它。
- 输出倒逼输入：讲解会立刻暴露「背下来了但没懂」的部分。
- 适用场景：备考、学新技术、写技术分享、给孩子讲作业、跨部门沟通。

## 二、四步流程

1. **选定概念**：写在纸的最上方，越具体越好（「TCP 三次握手」而非「计算机网络」）。
2. **假装教学**：用大白话向一个 12 岁孩子/非技术朋友解释，不许用行话；说不清的地方就是你没懂的地方。
3. **回到材料**：卡壳的地方翻书、查文档、看源码，重新理解后再讲一遍。
4. **简化与类比**：压缩成一段话 + 一个生活化类比；类比要能解释主要机制（并诚实标注类比失效的地方）。

## 三、示例：讲「数据库索引」

```text
第一遍（暴露问题）：
"索引就是让查询变快的东西。" —— 太空，不合格。

回查材料后第二遍：
"索引像书的目录：你想找'第三个实验'，不用一页页翻，
看目录直接翻到对应页码。数据库的 B+ 树索引让查找从
'翻整本书'（全表扫描）变成'按目录跳转'（对数级查找）。"

类比失效处：目录只能按一种排序找（最左前缀）；
书更新时目录也要重排（写放大）。
```

## 四、自检问题清单

- 我能用一句话说出它解决什么问题吗？
- 能举一个例子和一个反例吗？
- 它容易和哪个概念混淆？区别是什么？
- 如果去掉某个前提，结论还成立吗？
- 我能画出它的流程/结构图吗？

五个问题都能过 → 真懂；任何一问答不上 → 回到第 2 步。

## 五、变体与配合

- 费曼笔记本：每学一个概念写「如果给外行讲」的一段话，积累成自己的解释库。
- 输出形式升级：先对自己讲 → 写成短文 → 录 1 分钟语音 → 给真人讲并接受提问。难度递增，理解加深。
- 配合检索练习：讲完之后合上笔记，隔天再默讲一遍。
- 配合编程学习：讲清楚「这个 API 解决什么问题、什么时候不该用」，比背参数更接近掌握。

## 六、常见误区

- 把「复述原文」当「讲解」：背定义不是理解；必须换自己的语言。
- 类比替代理解：类比只是入口，最后仍要回到准确机制。
- 只挑会讲的讲：卡壳处才是价值所在，跳过就白学。
- 一次讲太多：一次一个概念，讲透为止。

## 七、检查清单

- [ ] 概念写在纸上，一次一个
- [ ] 讲解全程无行话（专业词出现前先解释）
- [ ] 卡壳处已回查并重讲
- [ ] 有一个生活化类比 + 标注失效边界
- [ ] 隔天能脱稿再讲一遍
