# ETL 数据集成指南

## 一、架构选择

- 批处理（T+1 全量/增量）适合报表与数仓分层；流式（CDC/Flink）适合实时看板与风控。
- ELT 趋势：先原样落仓（ODS），转换交给仓内 SQL，保留重算能力。
- 分层清晰：ODS（贴源）→ DWD（明细，清洗+维度退化）→ DWS（轻度汇总）→ ADS（应用/看板）。

## 二、抽取

- 全量：小表直接 TRUNCATE+INSERT 或快照表；增量：按更新时间/自增 ID 拉取，注意时钟回拨与边界重复。
- CDC（binlog/Debezium）能拿到删除与变更顺序，是同步升级的首选；拉 API 的源要处理限流、分页、幂等。
- 抽取要记录水位（watermark）：本次处理到的最大时间/ID，失败可从断点重跑。

## 三、转换与清洗

- 统一编码、时区、单位与字典映射（脏值映射表维护在维表，不散落代码）。
- 主键去重：同 key 多版本取最新（窗口函数或 ROW_NUMBER）；硬删除同步用「今天有、昨天没有」比对或 CDC delete 事件。
- 敏感字段在 DWD 层完成脱敏/加密；匿名化策略全链路一致。

## 四、加载与幂等

- 目标表优先分区表（按天），加载用「先写临时分区 → swap/rename → 更新元数据」，失败不污染主表。
- 幂等重跑：同一分区重复执行结果一致（覆盖写或先删后插），杜绝「重跑一次数据翻倍」。
- 大批量插入用批量语句/`COPY`/`LOAD DATA`；控制单批大小与事务长度。

## 五、调度与依赖

- 任务依赖用调度系统（DolphinScheduler/Airflow/XXL-JOB）管理，DAG 表达「上游就绪才跑」。
- 关键任务配置：失败重试（退避）、超时、告警（IM/电话分级）、SLA（最晚完成时间）。
- 跨天任务注意数据日期（data_date）参数传递，禁止在 SQL 里写死昨天。

## 六、数据质量

- 每次加载后跑校验规则：行数波动率、主键唯一、非空率、枚举值域、金额勾稽（明细汇总=总账）。
- 校验失败阻断下游并告警，而不是带病放行。
- 血缘可查：表级/字段级血缘让「上游改字段」的影响面可评估。

## 七、检查清单

- [ ] 增量抽取有水位，失败可断点重跑
- [ ] 清洗规则集中管理，含脏值映射
- [ ] 加载幂等，重跑不重复
- [ ] 调度有依赖、重试、超时、告警
- [ ] 数据质量校验入流程，异常阻断下游
