# 项目计划指南

## 一、启动与范围

- 先写一页项目章程：目标、成功标准、范围边界（明确不做什么）、里程碑、干系人。
- 范围蔓延是延期第一原因：新增需求走变更流程（评估影响 → 排期决策），不口头答应。
- 验收标准前置：什么算「完成」要在开工前说清，避免交付时各执一词。

## 二、任务分解（WBS）

- 把目标拆到可估算、可分配的工作包（1~5 人日一个粒度）。
- 拆分维度按交付物而非部门：先「做什么」再「谁做」。
- 任务之间依赖显式化：FS（完成-开始）、SS、FF；依赖多说明方案耦合重，先优化设计。

## 三、排期与关键路径

- 估算给区间（乐观/悲观）或加缓冲；三人以上估算（计划扑克）比一人拍板准。
- 找关键路径：决定项目最短工期的任务链；关键路径上的任务延期一天，项目延期一天。
- 资源冲突用甘特图暴露；过度并行会拖垮质量，串行瓶颈优先解决。
- 里程碑是检查点不是装饰：每个里程碑有可验证的产出。

## 四、风险登记册

- 每条风险记录：描述、概率（高/中/低）、影响、应对策略（规避/转移/减轻/接受）、负责人。
- 高概率高影响风险必须有预案与触发条件（「若供应商 3 日内未确认接口，则启动方案 B」）。
- 风险评审进例会：新风险入册、失效风险关闭，别让登记册变成一次性文档。

| 风险 | 概率 | 影响 | 应对 | 负责人 |
|---|---|---|---|---|
| 第三方支付接口延期 | 中 | 高 | 提前联调 + 备用通道 | 张三 |
| 核心开发被抽调 | 低 | 高 | 文档完善 + 交叉备份 | 李四 |

## 五、干系人管理

- 按权力-利益矩阵分层：重点管理高权力高利益者，保持知会低权力高利益者。
- 决策链路画出来：谁拍板、谁影响、谁执行；找不到拍板人的项目一定会卡在某个「再研究研究」。
- 沟通计划：什么人、什么频率、什么渠道、什么内容（例会纪要 / 双周高层简报 / 日站会）。

## 六、执行监控

- 燃尽图/里程碑达成率看趋势；进度落后时先看关键路径，再谈加班。
- 状态汇报三色制：绿（正常）、黄（有风险已可控）、红（需决策介入）；红色必须带选项与建议。
- 变更管理：影响（范围/成本/工期/质量）评估书面化，决策有记录。
- 收尾做复盘：目标达成情况、偏差原因、流程改进项，沉淀到组织过程资产。

## 七、检查清单

- [ ] 有章程，范围边界与验收标准明确
- [ ] WBS 拆到可估算粒度，依赖显式
- [ ] 关键路径已知，缓冲合理
- [ ] 风险登记册活在例会里
- [ ] 干系人沟通按计划执行，决策链清晰
