# 性能调优方法论

## 一、先定义，再优化

- 明确指标：RT（P50/P95/P99）、吞吐（QPS/TPS）、错误率、资源水位（CPU/内存/IO/网络）。
- 没有测量就没有优化：先用监控与压测确认瓶颈，再动手；「感觉慢」不是依据。
- 优化目标写清楚：如「下单接口 P99 从 800ms 降到 200ms @ 500 QPS」。

## 二、压测方法

- 流量要仿真：真实参数分布、读写比例、热点数据；录制回放优于凭空造数。
- 逐步加压找到拐点（吞吐不再升、RT 陡增、错误率抬头）；关注 P99 而非平均值。
- 压测环境尽量同构（同配置、同数据量）；缓存预热后再测稳态，冷启动数据单独记录。

## 三、定位路径

- 自上而下：入口 RT → 哪一层慢（网关/应用/DB/下游 RPC）→ 该层内部（锁/IO/GC/序列化）。
- CPU 高：火焰图（async-profiler / pprof）找热方法；注意「CPU 高但吞吐低」多半是自旋或锁竞争。
- RT 高：看等待——DB 慢 SQL、下游 RPC 超时、线程池排队（队列长度、拒绝数）。
- 内存：GC 频率与停顿、堆 dump 分析大对象与泄漏（ MAT / pprof heap）。
- IO：磁盘 util 与队列长度、网络重传/带宽；随机 IO 多考虑缓存与 SSD。

## 四、JVM 调优要点

- 先修代码再调参数：大对象、序列化、日志同步落盘是三大常见元凶。
- 堆大小：给足年轻代吞吐；G1/ZGC 看停顿需求；元空间与直接内存也要设上限防 OOM kill。
- 观察指标：GC 停顿 P99、GC 频率、晋升速度、safe point；调整一次只改一个变量。

## 五、常见优化手段

- 缓存：本地缓存挡热点读，注意一致性 TTL；多级缓存（进程内 + Redis）。
- 批量化：N 次查询合并批量接口；N+1 是 RT 杀手。
- 异步化：非关键路径（通知、积分、审计）改事件驱动；用户线程只做必须同步的部分。
- 并行化：独立下游调用并行发出（CompletableFuture），总 RT ≈ 最慢一支。
- 连接池与线程池：池大小按「IO 等待比」估算，压测验证；队列有界、拒绝有策略。
- 数据面：索引优化、冷热分离、读写分离；超大盘改分片。

## 六、检查清单

- [ ] 有明确量化目标与基线数据
- [ ] 瓶颈有证据（火焰图/慢SQL/线程dump），不是猜的
- [ ] 每次只改一个变量并复测
- [ ] 优化后回归功能与错误率
- [ ] 结果沉淀成文档：改动、数据、副作用
