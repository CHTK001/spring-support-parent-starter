# API 文档编写指南

## 一、接口条目结构

每个接口至少包含：

1. 一句话功能描述（动词开头：创建订单、查询余额）。
2. 请求方式与路径：`POST /v1/orders`。
3. 鉴权要求：是否需要 token、所需权限/签名。
4. 请求参数表：名称、类型、必填、默认值、约束（长度/范围/格式）、示例值、说明。
5. 响应说明：字段表 + 完整成功示例。
6. 错误场景：业务错误码、HTTP 状态、触发条件、处理建议。
7. 版本与变更：新增于哪个版本、最近变更说明。

## 二、参数描述要点

- 必填/选填明确；选填说明缺省行为（「不传默认按创建时间倒序」）。
- 类型精确：string(32)、int64、datetime(ISO 8601, UTC)、decimal(10,2)；金额用字符串或 decimal，禁用 float。
- 约束写全：最大长度、取值范围、枚举值全列出（含每个枚举含义）。
- 字段命名与实际报文一致；大小写敏感的字段别改写。

## 三、示例规范

- 请求示例完整：URL、头、体都可复制；curl + 主流 SDK 任选其一附上。
- 响应示例是「真实形状」：包含所有会出现的字段（含 null 字段的形态说明）。
- 给一个典型业务场景串联：创建 → 查询 → 回调/推送 → 关闭，比孤立接口更易懂。

## 四、错误码

- 全局错误码表 + 接口特有错误码分开维护；每个码给出含义与建议动作。
- HTTP 语义正确：400 参数错、401 未认证、403 无权限、404 不存在、409 冲突、429 限流、5xx 服务端。
- 错误响应结构统一：`{code, message, requestId}`；message 面向开发者，给出修复线索。

## 五、通用章节

- 快速开始：5 分钟跑通第一个请求（拿 key → 发请求 → 看响应）。
- 鉴权：token 获取、刷新、过期处理、签名算法（含可验证的样例）。
- 通用约定：分页参数、时间格式、时区、幂等、限流（配额与 429 处理）、webhook 重试策略。
- 变更日志：按版本列出新增/废弃/行为变更，破坏性变更给迁移指引。

## 六、OpenAPI 实践

- Schema 与实现保持同步（代码生成或契约测试），漂移的文档比没有文档更糟。
- description 写业务语义，别复述字段名；example 给真实感数据。
- 用 tag 分组接口；废弃操作标 `deprecated: true` 并在 description 给替代方案。

## 七、检查清单

- [ ] 每个接口七要素齐全（描述/路径/鉴权/参数/响应/错误/版本）
- [ ] 参数约束与枚举完整，类型精确
- [ ] 示例可复制执行，响应含真实形状
- [ ] 错误码统一结构且有修复建议
- [ ] 文档与实现同步（契约测试/代码生成）
