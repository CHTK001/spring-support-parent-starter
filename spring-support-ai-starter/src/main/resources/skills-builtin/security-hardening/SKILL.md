# 应用安全加固指南

## 一、认证与会话

- 密码用 bcrypt/argon2 慢哈希加盐存储；禁止 MD5/SHA1 裸用。
- 登录接口加验证码/滑块与失败锁定；连续失败按账号+IP 维度限流。
- 会话 token 短时效 + 刷新机制；登出与改密后旧 token 失效（黑名单或版本号）。
- OAuth/JWT：JWT 不放敏感信息（可解码），校验签名、过期、受众；刷新 token 单独存储与轮换。

## 二、授权

- 默认拒绝：未声明权限的接口一律 403；权限校验在服务端做，前端隐藏只是体验。
- 水平越权（改 ID 查别人数据）是最高频漏洞：所有按 ID 的查询/写入都要校验资源归属。
- 管理接口单独网段/路径前缀 + 二次鉴权；审计日志记录谁在何时改了什么。

## 三、注入与输入

- SQL 一律参数化/预编译；动态排序、表名用白名单映射，禁止字符串拼接。
- XSS：富文本入库前服务端净化（白名单标签），输出按上下文转义；CSP 作为兜底。
- SSRF：用户提供的 URL 做协议与目标校验（仅 http/https、禁内网段），出网走代理白名单。
- 反序列化只接受明确 schema；文件上传校验类型/大小/魔数，存储目录不可执行。

## 四、敏感数据

- 传输全站 TLS；内部服务间通信也要加密或隔离网络。
- 手机号/身份证/银行卡展示脱敏，存储按字段加密（密钥走 KMS/配置中心，不入代码库）。
- 日志脱敏：异常与业务日志禁止打印密码、token、完整证件号；日志中的异常堆栈不外泄内部路径。

## 五、依赖与配置

- 依赖漏洞扫描（OWASP Dependency-Check / npm audit / govulncheck）进 CI，高危阻断。
- 最小权限：数据库账号按服务拆分，只给必要库的必要权限；禁用 root 直连业务。
- 错误信息对外统一文案，不返回堆栈、SQL、内网地址；debug 端点生产关闭。

## 六、OWASP Top 10 快查

- A01 越权：资源归属校验全覆盖；A02 加密失败：敏感数据加密+TLS；A03 注入：参数化+净化。
- A04 失控设计：关键流程有风控；A05 配置错误：默认关闭 debug/目录列出；A06 脆弱组件：扫描阻断。
- A07 认证失效：慢哈希+锁定+会话轮换；A08 完整性失效：CI/CD 产物签名校验；A09 日志监控缺失：审计+告警；A10 SSRF：出口白名单。

## 七、检查清单

- [ ] 密码慢哈希，登录有限流与锁定
- [ ] 所有按 ID 的操作校验资源归属
- [ ] SQL 参数化，富文本净化，上传校验魔数
- [ ] 日志与错误响应无敏感信息
- [ ] 依赖扫描进 CI，高危阻断
